# Разделение next-gen2 по тайлам без общей площади

Историческая схема с сеткой 512/256. С 8 сентября 2026 года она заменена
[нарезкой без нахлёста 512/512](next_gen2_nonoverlap_tiles.md); числа ниже относятся к предыдущему запуску.

По уточнению пользователя 7 сентября 2026 года validation выделяется по тайлам, а не по целым снимкам.
Сетка и обработка ноутбука сохранены: полный вход 512×512, шаг 256, без контекста и обрезания краёв.
Одна сцена может содержать обе выборки.

Тайлы упорядочиваются по SHA-256 от seed 42, scene_id и координат x/y. Первые 20% составляют validation;
из остальных исключаются все окна, имеющие положительную площадь пересечения с любым validation-тайлом.
Проверка использует географические полигоны полных входов и учитывает пересекающиеся TIFF, включая nodata.
Общая граница без общей площади не считается утечкой. Выбор validation не зависит от разметки.

Проверка на `Переувлажнения\test_ml`, версия
`managed:1:git:757b1fad03ddc311a24088f2c29c246f0378d810`:

| Показатель | Значение |
|---|---:|
| Все полные окна | 29282 |
| Validation | 5856 |
| Кандидаты train | 23426 |
| Исключённые пересекающиеся train-окна | 20707 |
| Оставшиеся train-окна | 2719 |
| Снимки в каждой выборке | 14 |
| Пары с общей площадью после исключения | 0 |
| Train-окна с долей объекта >0,001 | 39 |
| Validation-окна с объектной разметкой | 149 |

Большое число исключений связано со случайным выбором validation и перекрытием исходной сетки 512/256.
Размер train после исключения не равен 80% исходного пула; новые тайлы взамен исключённых не добавляются.
CrossEntropy-веса `[0.0011149754282087088, 1.9988850355148315]` и sampler вычислены только по оставшимся train.
В manifest записаны координаты всех окон, индексы каждой части и число исключений по снимкам.
Независимая проверка заново строит географические прямоугольники из TIFF и подтверждает отсутствие
общей площади, раздельность индексов и использование sampler только для train.

Тесты проверяют пересечения внутри одного TIFF и между разными TIFF, допустимость общей границы,
работу на одном снимке, неизменность выборок при перестановке файлов и независимость train-весов от
изменения разметки в областях validation. Ранняя остановка и best остаются по F1 с patience 50;
пределы — 300 эпох и 10800 секунд, batch 32, после обучения включена штатная псевдоразметка.

В первоначальном next-gen2 из run `e0cc7417bec04d00898e05ccb153d0b4` индексы были различны,
но 5850 из 5856 validation-окон пересекались с train того же TIFF. Покрывались 92,0936% пиксельных
позиций validation, включая фон и повторения пикселя в соседних окнах. Это схема исходного ноутбука.
Промежуточное разделение по сценам устраняло пересечения, но не соответствовало уточнённой постановке;
его запуск остановлен, лучшие веса сохранены отдельно.

Дополнительно проверены сохранённые запуски предыдущих вариантов:

- `legacy`: задание `d8a4d6df-735c-45b4-b900-7cfeb6697a98` от 28 августа 2026 года,
  датасет `Переувлажнения\test_ml`, MLflow `5f178286c0c641e8ab2ea90f84b172ea`.
  По сохранённым настройкам и снимку данных восстановлены окна 512, шаг 256, контекст 128:
  18427 кандидатов train и 120 фиксированных validation-тайлов. Полный вход каждого из 120
  validation-тайлов пересекается с обучающим пулом; даже центральная область валидационной разметки
  каждого из них встречается в полном входе кандидатов train. У 10 из 120 пересекаются также
  центральные области расчёта лосса train и validation. Это проверка доступного обучающего пула:
  конкретные случайные выборки train по эпохам не сохранялись, поэтому фактическую частоту
  попадания этих окон в batch восстановить нельзя.
- `next-gen`: задание `ebe7f7ec-e64c-4ee9-a558-86d014561c0a` от 7 сентября 2026 года,
  датасет `Заболачивание\test_ml`, MLflow `6f9dc83403614fe4a5aa284f81a656a6`.
  Сохранённый в MLflow manifest содержит `scene_fold`, четыре сцены train и одну validation,
  `spatial_purge=true`: 149 пересекающихся окон исключены, 6748 оставлены, остаточное число
  географических пересечений равно нулю. Здесь проверен фактический архивный manifest;
  эти числа относятся к указанному запуску и его датасету.
