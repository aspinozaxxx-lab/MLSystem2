# Ускорение подготовки next-gen2 и исправление отмены задания

Проверка 7 сентября 2026 года на `gpu-mlserver`: 32 логических CPU, 128 ГБ RAM, NVMe,
RTX 5090. Рабочий запуск `7a3cdc45-3ae0-478f-9bd7-e735ba335c85` использовал
`next_gen2`, batch 32 и принудительные `num_workers=0`. Первая эпоха заняла 507,98 секунды.

## Найденные причины

- Параметр worker переопределял серверные восемь загрузчиков нулём.
- Для каждого полного окна создавалась обработка `boundless`, хотя выхода за границы нет.
- Маска валидности TIFF читалась, но сразу заменялась нулями согласно правилам ноутбука.
  Профиль показал дополнительные расходы на создание окружений Rasterio и AWS-сессий.
- Процесс ранее удалённого задания `6f5febb2-5235-47b8-95bb-eb70360deee7` продолжал работать:
  около одного CPU и 4 ГБ GPU RAM. Журнал API подтвердил `DELETE` в 19:37:25, строки БД и
  рабочей папки уже не было. Остаточная группа остановлена отдельно; текущий запуск сохранён.

## Изменения

Next-gen2 читает полные окна напрямую, без `boundless` и неиспользуемой маски TIFF.
Загрузчики используют серверное `num_workers`, по умолчанию 8; префетч ограничен двумя batch
на процесс, вместо потенциально всей эпохи. Процессы загрузки пересоздаются между эпохами,
сохраняя порядок выборок и потребление RNG основной программы. Растущего кэша тайлов нет.
Нормализация, разбиение, sampler, маски, loss и параметры оптимизатора сохраняются.

Отмена сначала посылает `SIGTERM` всей группе. После пяти секунд ожидания оставшиеся процессы
получают `SIGKILL`, затем завершение проверяется ещё до двух секунд. Только после подтверждения
очищаются PID и временные данные. Worker учитывает живых потомков даже после выхода лидера группы.
При невозможности остановки API возвращает ошибку и сохраняет задание с рабочей папкой.
Штатная остановка с сохранением лучших весов по-прежнему использует кооперативный запрос.

## Замер загрузки

Замер выполнен отдельно от рабочего обучения на его неизменяемом снимке разметки:
14 сцен, 17 569 обучающих окон. Во всех случаях одни и те же 512 случайно выбранных окон
512×512, seed 101, batch 32, одинаковый порядок. GPU-модель не запускалась.
Время включает запуск итератора, получение batch и контрольные суммы; начальная подготовка
датасета около 11 секунд измерялась отдельно. Профилировщик в замерах времени выключен.

| Подготовка | Время 512 тайлов | Тайлов/с |
|---|---:|---:|
| Исходная, один процесс | 10,425 с | 49,1 |
| Прямое чтение, один процесс | 4,099 с | 124,9 |
| Прямое чтение, восемь процессов | 2,614 с | 195,9 |

Объединённая SHA-256 изображений и масок во всех случаях:
`3dccd2194d7b0db421b064904b161583630c80e163f068bbab648df0c94b2e88`.
Ускорение подготовки составляет около 4×; оно не означает такое же ускорение всей эпохи.
Начальное построение статистик и GPU-вычисления в этот коэффициент не входят.

Тест сравнивает последовательные и параллельные загрузчики на двух эпохах: изображения,
маски, метаданные, случайные числа между batch и итоговое состояние Torch RNG совпадают.
Linux-тест отмены запускает настоящего потомка, игнорирующего `SIGTERM`, в двух вариантах:
при живом и при уже завершившемся лидере. Подтверждены завершение потомка и очистка данных.
Отдельно проверено сохранение PID и рабочей папки, если остановку подтвердить не удалось.
Общий локальный набор: 595 тестов пройдено, четыре пропущено; Ruff и compileall пройдены.
Проверки реальных групп процессов выполнены на Linux-сервере, в том числе после добавления
проверки живых потомков для worker. Они проходят и для уже завершившегося лидера группы.
