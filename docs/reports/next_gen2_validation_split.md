# Независимая валидация next-gen2

Историческая проверка разделения по сценам. По уточнению пользователя эта схема заменена
[разделением по тайлам с исключением общей площади](next_gen2_tile_split.md); числа ниже относятся
к остановленному промежуточному запуску `9009801c-282a-4f23-b8b6-e0a964b0364f`.

Проверка 7 сентября 2026 года выполнена на датасете `Переувлажнения\test_ml`, версия
`managed:1:git:757b1fad03ddc311a24088f2c29c246f0378d810`.

В run `e0cc7417bec04d00898e05ccb153d0b4` сохранённое разбиение ноутбука содержало 17569 обучающих,
5856 валидационных и 5857 резервных тестовых тайлов. Индексы всех частей строго различались, но сцены
были общими. Из-за окон 512×512 с шагом 256 пространственно пересекались с train 5850 из 5856
валидационных окон. 92,0936% позиций пикселей validation покрывались обучающими окнами того же TIFF.
Это геометрическая оценка, включая фон и повторный подсчёт пикселя в разных validation-окнах;
пересечения разных TIFF здесь не учитывались и могли дополнительно увеличить утечку.

По согласованному изменению новые запуски делят целые сцены через существующий `scene_fold` с seed 42.
Из 14 снимков 3 выделены для validation, остальные 11 — для train. Удаляются обучающие окна,
пересекающие полную территорию validation TIFF с запасом в один исходный пиксель. Полные границы нужны,
поскольку next-gen2 включает nodata в оценку. Отдельный резерв test больше не выделяется.

Независимая проверка на серверных TIFF после изменения:

Веса CrossEntropy `[0.001735252677462995, 1.9982647895812988]` вычисляются после разделения и
пространственного исключения, только по train. WeightedRandomSampler получает только train Dataset;
validation использует последовательный сэмплер. Validation вызывает `model.eval()` и `torch.no_grad()`;
optimizer step выполняется только в обучающем цикле. Тесты дополнительно проверяют неизменность
параметров, буферов и градиентов после validation, а также независимость train-весов и сэмплера от
изменения валидационной разметки.

Best и ранняя остановка новых запусков используют максимальную F1 при пороге 0,5. При равном F1
сохраняется более ранняя эпоха; равенство не сбрасывает patience. Scheduler остаётся исходным
`ReduceLROnPlateau` по loss. Tag `checkpoint_selection_metric=quality_f1` отличает новые MLflow runs
от исторических, где best фактически был сохранён по минимальному loss.

Профиль и шаблон: до 300 эпох, 10800 секунд, patience 50, batch 32. Нарезка, нормализация,
CrossEntropy, балансировка и инференс с гауссовым усреднением и порогом 0,9 сохранены.
Прежнюю F1 нельзя напрямую сравнивать с новой: изменена сама валидационная выборка и устранено
пересечение с обучающими территориями.
