# Статистика использования Гровики

Счётчик Яндекс Метрики для `grovika.ru`: **113578839**. Владелец прямо разрешил
Вебвизор; записи сеансов и отчёты открываются в Метрике, раздела аналитики в Гровике нет.

## Подключение

В `/etc/mlsystem2/training-ui-api.env` задаётся `MLSYSTEM2_METRICA_COUNTER_ID=113578839`.
Эта переменная не является секретом. Пустое значение или `0` отключает интеграцию.
После изменения перезапустить `mlsystem2-training-ui-api.service`.
Код поставляется обычным CI/CD; миграции и дополнительные сервисы не нужны.
Секрет сессии и пароли остаются только на сервере, полный env-файл не выводить.

Скрипт загружается только после входа. Используются `defer: true`, `webvisor: true`,
`clickmap: true`, `accurateTrackBounce: true`. Переходы SPA считаются явным `hit`,
а автоматическое отслеживание ссылок выключено. Выход останавливает счётчик.
Вебвизор фиксирует взаимодействие с интерфейсом, включая отображаемое содержимое страниц;
события страниц и функций не содержат текста разметки, логина, ключей сущностей или query.

## Отчёты

- **Популярные страницы**: отчёт «Содержание → Популярное». Виртуальные адреса
  `/#/usage/<категория>` объединяют разные датасеты и снимки одной страницы.
- **Функции**: отчёт «Параметры событий». Ветка
  `grovika → features → UserID → название функции → исход` содержит
  русское название действия; исход — «Успешно» или «Ошибка» по HTTP-ответу.
  Событие означает запрос пользователя, а не завершение длительного задания.
- **Пользователи**: группировка «Аудитория → UserID посетителя» и ветки
  `grovika → pages → UserID` и `grovika → features → UserID`. Эти ветки позволяют разделять
  аккаунты, которыми пользовались в одном браузере, независимо от связи ClientID и UserID.
- **Сеансы**: вкладка «Вебвизор».

Параметры событий передаются без ручной настройки целей. Для отчётов по конверсиям
можно создать цели типа «JavaScript-событие»: `grovika_training_start`,
`grovika_training_continue`, `grovika_pseudo_create`, `grovika_test_f1_calculate`,
`grovika_dataset_publish`, `grovika_model_export` и другие коды из
`frontend/src/utils/usage.ts`. Цель приходит только при успешном HTTP-ответе
и без повторной передачи параметров: один запрос даёт одно событие функции.
Метрики целей и число событий не равны количеству завершённых обучений.

API-опрос очереди, чтение TIFF, автосохранение черновиков, фоновые сравнения и
автоматические операции worker не создают событий функций. Просмотры засчитываются
только после авторизации и принятого перехода, включая смену датасета внутри страницы.
Блокировщик счётчиков может исключить визит из Метрики; локального дублирующего сбора нет.
Статистика начинается после установки обновления; старые посещения не восстанавливаются.
Данные в интерфейсе Метрики появляются с задержкой.

## Связь UserID с аккаунтом

Метрика получает непрозрачный ID, а не имя человека. ID одинаков для всех браузеров
одного канонического аккаунта; вход по псевдониму не меняет его. При замене секрета
сессии ID изменится. Соответствие можно получить на сервере следующей командой;
она выводит только логины и их ID, без паролей, токенов и окружения:

```bash
set -a
. /etc/mlsystem2/training-ui-api.env
set +a
cd /opt/mlsystem2/repo
.venv/bin/python - <<'PY'
from mlsystem2.training_ui_api._config import get_config
from mlsystem2.training_ui_api._usage import metrica_user_id
config = get_config()
for user in config.frontend_users:
    print(user.username, metrica_user_id(user.username, config))
PY
```

Приватные функции здесь используются только для диагностики внутри модуля;
новый публичный CLI или API списка пользователей не вводится.

## Проверка доставки

Проверить установленный коммит, API и frontend по обычному runbook доставки.
`/api/v1/usage/config` без сессии возвращает `401`, с сессией — счётчик и ID,
заголовок `Cache-Control: no-store`. На новой авторизованной вкладке загружается
`https://mc.yandex.ru/metrika/tag.js?id=113578839`; один переход даёт один `hit`.
Переход через охрану несохранённого черновика, опрос очереди и TIFF не дают лишних
просмотров или целей. При выходе прекращается отправка событий прежнего аккаунта.

Официальные правила: [SPA-сайты](https://yandex.ru/support/metrica/ru/code/counter-spa-setup),
[UserID](https://yandex.ru/support/metrica/ru/objects/set-user-id),
[параметры событий](https://yandex.ru/support/metrica/ru/data/visit-params-data).
