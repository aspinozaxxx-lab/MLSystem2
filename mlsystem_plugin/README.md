# QGIS-плагин MLSystem2

Плагин запускает серверное распознавание AOI и сохраняет проверку кандидатов в локальном
GeoPackage. Он не отправляет снимки, WMS, скриншоты или клиентские пути: тело задания содержит
только `class_id`, GeoJSON AOI и её CRS.

## Совместимость и установка

Метаданные разрешают QGIS `3.34–4.x`. Фактическая автоматическая проверка выполнена в QGIS
`4.0.0 Norrköping`, Qt `6.8.1`. Для установки скопируйте всю папку `mlsystem_plugin` в каталог
профиля QGIS `python/plugins`, затем включите «MLSystem2 — проверка псевдоразметки» в менеджере
плагинов.

Для упаковки из корня репозитория в PowerShell:

```powershell
Compress-Archive -Path mlsystem_plugin -DestinationPath mlsystem_plugin.zip -Force
```

Архив должен содержать верхнюю папку `mlsystem_plugin` и файл `metadata.txt` внутри неё.

## Подключение и распознавание

1. Откройте панель через меню «Вектор → MLSystem2».
2. Адрес рабочего сервера `https://grovika.ru` и пользователь `mluser` уже заполнены. Введите
   пароль этой учётной записи и нажмите «Войти и загрузить классы». Плагин вызывает штатный
   `/api/v1/auth/login`, получает серверную сессию и использует её для дальнейших запросов.
   В `QgsSettings` сохраняются только URL и имя пользователя; пароль и сессионная cookie не
   записываются в настройки, репозиторий или журнал.
3. Нажмите «Проверить и загрузить классы» и выберите класс. Рядом показана зафиксируемая версия
   последней пригодной модели.
4. Задайте AOI одним способом:
   - «Нарисовать»: левая кнопка добавляет вершины, правая завершает полигон;
   - «Текущий охват»;
   - выберите полигональный слой в поле «Слой выделения», выделите объекты и нажмите
     «Из выделения».
5. Нажмите «Запустить распознавание». Запросы и polling выполняются через Qt Network и не
   блокируют интерфейс. После временной сетевой ошибки polling повторяется с увеличенной паузой.
   «Отменить задание» прекращает ожидание и запрашивает серверную отмену.

WMS остаётся обычной визуальной подложкой QGIS и не участвует в запросе.

## Сессия проверки

Для каждого `job_id` создаётся `pseudolabel_<job_id>.gpkg` со слоем `candidates`. Если проект
сохранён, файл находится в `.mlsystem2/review_sessions` рядом с проектом. Для несохранённого
проекта используется каталог данных приложения QGIS; точный путь всегда показан в панели.
Кнопка «Открыть сохранённую сессию…» продолжает работу после перезапуска.

Кандидаты не удаляются при решении. Поле `review_status` меняется между `new`, `annotation`,
`hard_negative`, `discarded`, `split`, `exported`; стиль слоя различает статусы. Доступны фильтры,
сортировка по исходному порядку, confidence и площади, переходы и приближение к текущему объекту.

Горячие клавиши действуют только при открытой панели с активной сессией:

- `1` — в разметку;
- `2` — hard_negative;
- `3` — выкинуть;
- `N` или `Space` — следующий;
- `P` — предыдущий;
- `S` — разбить;
- `Ctrl+Z` — отменить одно логическое действие;
- `Ctrl+Shift+Z` — повторить.

## Undo, redo и разбиение

Решения сначала изменяют только persistent staging. Один `QUndoCommand` включает смену статуса,
время проверки и автоматический переход, поэтому одного `Ctrl+Z` достаточно независимо от фокуса
на карте или в dock. QGIS не получает два несвязанных undo stack. При скрытии панели или закрытии
сессии shortcuts отключаются, и стандартный `Ctrl+Z` снова принадлежит QGIS.

«Разбить» сначала раскрывает MultiPolygon, затем преобразует геометрию в локальную
равноплощадную CRS и рекурсивно режет Polygon по длинной стороне bounding box. Части больше
максимального порога делятся повторно, части меньше минимального порога отбрасываются. До изменения
проверяется валидность и потеря общей площади не более 1%. Родитель получает `split`, дети — `new`,
`parent_candidate_id` и стабильные UUID. Добавление всех детей и смена родителя — одна undo-команда.
Автоматическое разбиение выключено по умолчанию.

## Рабочие слои и применение

Явно выберите разные полигональные слои «Разметка» и «Hard negative». Активный слой QGIS не
используется и не меняется. Через «Сопоставить поля» укажите только существующие поля для класса,
источника, confidence, candidate ID и версии модели. Схема слоёв не изменяется; значение целевой
метки hard_negative не выдумывается. Поле `candidate_id` обязательно для применения, поскольку оно
обеспечивает идемпотентность.

«Применить результаты» предварительно проверяет оба слоя и все преобразования CRS, затем добавляет
объекты в edit buffers двух слоёв внутри согласованных edit commands. При ошибке обе команды
откатываются, а staging не меняется. Повторный запуск сверяет `candidate_id` и не создаёт дубликаты.
Плагин намеренно не выполняет commit: проверьте результат и сохраните или откатите каждый целевой
слой штатными средствами QGIS. Если целевые правки были откатаны, повторное применение снова увидит
отсутствующие `candidate_id` и восстановит их.

## Типовые ошибки

- `AUTH_FAILED` — проверьте имя пользователя и пароль MLSystem.
- `SESSION_EXPIRED` — срок сессии закончился; снова введите пароль и выполните вход.
- Класс отсутствует — обновите список; у класса должна быть завершённая модель с доступным best.pt.
- Нет снимков — сервер не нашёл TIFF, пересекающий AOI.
- Частичное покрытие — результат допустим, фактический процент показан как предупреждение.
- AOI отклонена — уменьшите площадь/число вершин или исправьте геометрию и CRS.
- Слой недоступен/только для чтения — верните слой в проект или выберите редактируемый provider.
- Не сопоставлен candidate ID — создайте подходящее поле самостоятельно и выберите его в диалоге;
  плагин не меняет схему автоматически.
- Разбиение отклонено — измените пороги либо исправьте исходную геометрию; частичные изменения не
  сохраняются.

Технический код ошибки без пароля и сессионной cookie пишется в журнал QGIS «MLSystem2»; короткое
сообщение показывается в панели и message bar.

## Тестирование

Чистые контракты запускаются обычным Python:

```powershell
pytest -q mlsystem_plugin/tests/test_contracts.py
```

Тесты GeoPackage, QUndoStack, CRS, разбиения и целевых слоёв запускаются Python целевого QGIS:

```powershell
$env:QT_QPA_PLATFORM='offscreen'
& 'C:\Program Files\QGIS 4.0.0\bin\python-qgis.bat' mlsystem_plugin\tests\qgis_test_suite.py
```

Для ручной проверки создайте два редактируемых полигональных слоя с текстовым полем
`candidate_id`, настройте сопоставление, выполните все три решения, undo/redo и разбиение, затем
дважды нажмите «Применить результаты» и убедитесь, что число объектов после второго раза не выросло.
