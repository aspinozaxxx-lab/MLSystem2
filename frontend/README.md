# Frontend MLSystem2

Стек: React + TypeScript + Vite. OpenAPI-типы и production static собираются командами:

```bash
npm run generate:api
npm run typecheck
npm test
npm run build
```

В production `frontend/dist` отдаётся статикой, сервер Node.js не нужен, а все запросы `/api/v1/*`
обрабатывает `training_ui_api`.

Фронт не обращается к Postgres и не хранит defaults в constants: датасеты, модели, шаблоны, очереди и
результаты берутся только из FastAPI. Иерархия каталога — `класс → датасеты`; класс задаёт тип снимков
`Канопус` или `Ортофото`, а все операции обучения и результатов выбирают конкретный датасет.

Редактор датасетов распознаёт отмену по физической клавише `Z`, поэтому `Ctrl+Z` и `Ctrl+Я` работают одинаково.
`Del` удаляет выбранные вершины, а если вершины не выбраны — выделенный полигон; оба действия используют общую
историю отмены.
В редакторе обычного per-image датасета снимок показывает число версий разметки в пределах своего класса.
Панель «Версия разметки» выбирает существующий вариант, создаёт независимую копию текущего черновика
или пустой вариант. Видны использующие датасеты, включая зависимые управляемые наборы. При удалении
нужно выбрать замену; все активные использования будут переключены при публикации. Переключение,
создание, удаление и геометрия разных вариантов сохраняются одним личным черновиком и отменяются
обычной историей. Публикация общей версии обновляет связанные датасеты. Сущности находятся в БД,
Git получает собранные файлы. У добавленных из класса источников тестовых областей панель выбирает
версию без её изменения: публикация фиксирует эталон, обновление исходной версии применяется только явно.
У отдельно импортированных тестовых TIFF/GeoJSON панели версий нет; у виртуального набора варианты
выбираются в исходном классе.

Тестовую область можно выбрать и перетащить целиком за внутреннюю часть; форма, части и отверстия
сохраняются, смещение привязывается к целым пикселям исходного TIFF. Выбор числового размера заменяет
выделенную область квадратом вокруг текущего центра. Сохранённая квадратная рамка распознаётся по
геометрии и пиксельной сетке, дополнительные поля API не нужны. Вершины, правка рёбер, выбор вершин рамкой
и вырезание отверстий доступны только при выборе «Свободный контур». У фиксированной рамки виден только
контур; перенос полностью за снимок отменяется, частичный выход сохраняется для заполнения nodata.
Перенос и изменение размера используют обычные автосохранение черновика и историю отмены.

В общем редакторе датасетов и тестовых разметок кнопка с ножницами «Вырезать отверстие в полигоне»
доступна после выбора одного объекта. Контур рисуется строго внутри одной части `Polygon/MultiPolygon`,
без пересечения, касания или охвата других отверстий; двойной клик завершает вырез, `Esc` отменяет эскиз.
Меняется геометрия исходного объекта без нового feature, изменения ID, свойств, роли или типа.
Вырез входит в общую историю отмены и автосохранение; вершины отверстия можно править обычным инструментом.
Чтобы удалить отверстие, выделите все его вершины и нажмите `Del`. Если после удаления выбранных вершин
осталось бы меньше трёх, отверстие также удаляется целиком; внешний контур и остальные отверстия сохраняются.
Удаление отверстия использует то же автосохранение и отменяется одним `Ctrl+Z` / `Ctrl+Я`.
Если отверстие вынесено за внешний контур, серверное восстановление топологии может превратить его в
отдельную часть `MultiPolygon`. `Del` удаляет и такую часть, когда выбраны все её вершины или осталось бы
меньше трёх: остальные части и их отверстия сохраняются. Удаление всех частей через выбор вершин
блокируется; для удаления всего объекта используется обычное выделение полигона без выбора вершин.
При правке выбранные объекты исключены из привязки Snap, чтобы вершины не прилипали к собственным
прежним рёбрам; привязка к соседям сохранена. При рисовании привязка снова использует все видимые объекты.
Подсветка выбранных вершин перерисовывает слой, не вызывая `feature.changed()`: иначе Modify
перестраивает индекс объекта и теряет текущую вершину, даже когда кнопка остаётся зажатой.
Запоздалые `singleclick` и отложенное выделение вершины относятся только к своему поколению жеста:
начало нового нажатия делает прежний клик неактуальным даже после быстрого отпускания.
Границы жеста отслеживаются по реальным `pointerdown`/`pointerup`/`pointercancel`, без имитации отпускания.
Кнопка на карте раскрывает всё рабочее поле с инструментами через полноэкранный API браузера либо резервный режим
поверх всей области окна, если API запрещён. Выход выполняется повторным нажатием или клавишей `Esc`, после чего
OpenLayers пересчитывает размер карты.

Форма запуска содержит четыре раскрывающихся раздела: модель и датасет (открыт по умолчанию), подготовка данных,
обучение и условия остановки. Максимум эпох находится в условиях остановки. Две опции — последующая
псевдоразметка и второстепенный приоритет — всегда видны, как и автоматически составленное описание запуска.
Выбор эксперимента MLflow убран; ручные запуски используют `MLSystem2`.

Поля компактные, форма использует ширину большого экрана. Нарезка показана полями слева и схемой тайла справа:
полезный центр равен `tile_size − 2 × context`. Баланс positive / hard negative / background представлен
трёхцветной полосой с двумя разделителями и редактируемыми процентами; мышь, клавиатура и числовой ввод
сохраняют сумму 100%. Валидация отображается в процентах, лимит времени — в минутах, но API получает доли
и секунды. При ошибке раскрывается раздел с соответствующим полем. Сворачивание сохраняет значения и файлы.

Параметры, подсказки и настройки конвейеров приходят из API-схемы и шаблона; ограничения legacy / next-gen /
next-gen2 сохраняются. DataLoader workers/prefetch, seed, smart tiling, device и task задаются defaults модулей
MLSystem2. Число каналов определяется типом класса: 4 для Канопуса и 3 для ортофото.

Страница `Шаблоны обучения` показывает дерево: первый уровень — базовые шаблоны сетей, второй уровень —
созданные шаблоны конкретных датасетов. Шаблон датасета создается копированием текущего базового шаблона сети,
может быть удален с подтверждением и используется как defaults для ручного запуска и автоматизации. Если
датасетного шаблона нет, API использует базовый шаблон сети. У каждого поля есть кнопка `установить для всех`,
которая применяет текущее значение этого поля ко всем существующим шаблонам.

Страница `Автоматизация` строит матрицу `датасет × модель` из `GET /api/v1/automation`. В каждой ячейке есть две
галочки: синяя для auto training и красная для auto pseudo-markup. Изменения сохраняются сразу через
`PUT /api/v1/automation/rules`. При отключении глобального switch frontend сначала показывает предупреждение:
незавершенные результаты будут потеряны, очередь automatic jobs будет очищена, а текущий automatic process будет
остановлен. После подтверждения отправляется `PUT /api/v1/automation/enabled` с `enabled=false`. Frontend не решает,
какие jobs создавать: он только сохраняет правила, а синхронизацию по `dataset_version` выполняет FastAPI worker.

Страница `В процессе` показывает единую очередь jobs. Ручная псевдоразметка идет выше ручного обучения,
ручное обучение выше auto псевдоразметки, auto псевдоразметка выше auto обучения. Строки инференса подсвечены
красноватым, строки обучения — голубоватым; стрелки управления остаются для ручных queued jobs.

Страница `Результаты` после карточек классов показывает сначала запланированные и выполняющиеся задания, затем
последние 20 успешных изменений результатов: обученную сеть или созданную псевдоразметку.
Ссылки «Grafana» и «Снимки» — кнопки с иконками справа от заголовка «Рабочая панель»;
на широком экране они имеют подписи и обычную ширину, в компактной версии — только иконки.
Отдельных карточек сервисов, MLflow и Mapflow на главной нет.
На главной вместо таблицы последних изменений показаны новости с независимыми плашками «Фичи» (большие статьи)
и «Исправления» (короткие записи `updates`). По умолчанию включены только «Фичи»; доступны обе категории вместе
и отключение обеих. Фильтры не меняют постоянные адреса публикаций. Клик по активному заданию на общих страницах открывает страницу соответствующего датасета, а
на странице датасета обучение или псевдоразметка со статусом `queued`/`running` отображаются в основной таблице;
клик по такой строке открывает страницу параметров задания. Отдельная ссылка MLflow остается кликабельной, если она уже есть. Клик по
завершенной строке открывает страницу соответствующего датасета.
На странице датасета кнопка `Сделать псевдоразметку` открывает modal с тремя взаимоисключающими источниками
снимков: датасет MLMarkup, папка из `/api/v1/image-folders` или загруженный txt. В списках датасетов и папок
показывается количество снимков и только источники того же типа, что 3- или 4-канальная модель; в таблице
псевдоразметок рядом со ссылкой на GeoJSON показывается размер файла.
Рядом с успешным результатом обучения есть кнопка `zip`: она предлагает имя
`{имя geojson-разметки без расширения}_{kanopus|ortho}` и скачивает архив Triton CPU через endpoint результата обучения.
Страница `Экспорт моделей` показывает последние успешные модели по датасетам, по умолчанию
отмечает основные датасеты классов, позволяет поменять имя выгрузки и optional `sample_size` для каждой модели и скачивает
один общий архив через `POST /api/v1/results/training/triton-zip`.

В меню `Экспорт` страница `Создание тестовых разметок` создаёт одно задание по выбранному классу
и одному датасету. Размер тайла, диапазон итогового состава, минимум объектов, оптимизация и исключение
граничных объектов сохраняются после изменения отдельно для датасета через
`PUT /api/v1/test-sample-batches/options/{dataset_key}/settings`; варианты возвращают `creation_settings`.
Без оптимизации случайный допустимый состав не требует сети и псевдоразметки; расширенный пул до
`3 × Nmax` оставляет выключенные запасные тайлы для ручного выбора. Без обученной сети галочка
недоступна с пояснением по наведению или касанию. Внизу `GET /api/v1/test-sample-batches` показывает
отдельную очередь создания: ожидающие можно переставить или удалить, выполняемое — отменить.
Форма остаётся доступной во время создания. На широком экране источник и параметры расположены рядом.
На iPhone 15 поля расположены в два столбца,
списки отображаются целиком без внутренних вертикальных прокруток, основные действия имеют область касания
не меньше 44 px. Очередь показывает все активные задания и дополняет список историей до пяти строк;
если активных больше пяти, видны только они, а без активных — пять последних завершённых.
На странице `Каталог тестовых разметок` расположен каталог `класс → датасет → выборки` с количеством включённых тайлов, метриками и признаком
основной выборки. Кнопка общего скачивания открывает по центру экрана вертикально прокручиваемый список в три
колонки. Компактная плашка показывает `Класс_датасет`, дату создания и звезду основной разметки; основные
отмечены заранее, пустые недоступны, а выбор другой разметки того же датасета снимает предыдущую. `Снять все`
очищает выбор. На узком экране список становится одноколоночным. Для одиночного и группового скачивания
модальное окно предлагает полный состав с превью либо только TIFF и GeoJSON.
Маршрут `#/test-markups/{sample_id}` открывает редактор со сводкой, метриками и галереей: тайлы можно выключать
и включать обратно, выборку — переименовать, назначить основной или удалить с подтверждением. Галерея загружает
только JPEG-миниатюры до 384 px. Клик загружает полноразмерный PNG в почти полноэкранное модальное окно, где
доступны масштаб колесом и кнопками, режим 1:1, пропорциональное вписывание целого изображения по ширине и высоте
и перемещение перетаскиванием, в том числе при базовом масштабе. Пересчет F1 запускается вручную, ZIP содержит только
включенные тайлы и нумерует их последовательно. Оптимизатор редактора рассматривает все тайлы, принимает диапазон
их количества и минимум объектов, после чего включает состав с максимальным пиксельным либо объектным F1.

На странице датасета результатов зелёная плашка подтверждает актуальность тестового F1 всех успешных сетей.
При смене основной выборки, её состава или inference-шаблона показываются красная плашка и кнопка массового
пересчёта. В строке сети отображается отдельный тестовый F1, а карточка датасета на странице `Результаты`
показывает F1 самой новой оценённой сети зелёным либо оранжевым при потере актуальности. Таблицы сетей и
псевдоразметок используют компактные колонки без горизонтальной прокрутки на обычной ширине страницы; прокрутка
остаётся только для узких экранов.

Тестовый F1 в карточке датасета и строке сети — ссылка `#/test-f1/{training_result_id}` на карту оценки.
`TestF1Page` выбирает независимый TIFF и тип объектов, показывает общий и поснимочный F1; `PseudoMap` общий
с просмотром псевдоразметки и добавляет независимые переключатели эталона/прогноза и пиксельные TP/FP/FN.
При наличии сохранённых ID контуры эталона и прогноза строятся по отдельным объектам, а не по общей
бинарной маске: соприкасающиеся участки остаются отдельными полигонами в обоих режимах F1. Контуры рисуются выше
заливки TP/FP/FN; пиксельные области сравнения и сохранённые метрики не изменяются.
На телефоне снимок выбирается селектором; сохранены каналы, непрозрачность, жесты и полный экран.
GET читает сохранённые маски без ML-заданий. Для старого расчёта без масок кнопка подготовки делает
идемпотентный POST и опрашивает состояние. Устаревшая оценка и отсутствующий TIFF сопровождаются пояснением.
